# v1.3 屏蔽听众

日期：2026-09-24。范围：在线附近发现、邀请及共听；沿用本地 A/B 身份，不新增正式 QQ 接入或举报后台。

## 用户操作

- 附近听众卡片、待处理邀请及共听页提供“屏蔽”。展开说明并确认后提交，不因误点入口直接执行。
- 屏蔽后双方互不出现在附近，双向邀请不可发送；待处理邀请取消，已有共听结束。对方只看到邀请结束或房间结束，不收到“你被屏蔽”的通知。
- 设置 → 已屏蔽听众查看屏蔽时的匿名代号、日期并解除；发现关闭时仍可管理。最多保留 100 位。
- 解除只删除本账号的屏蔽。对方也屏蔽自己时仍不可相遇；不恢复旧邀请、旧房间或自动播放。
- 收藏、收到的歌曲、足迹等音乐记录保持原样。

## 数据和边界

- 屏蔽依据稳定账号编号；暂停/重开发现、刷新或重新登录不会绕过。客户端提交当前听众编号或自己的房间编号，不能指定任意账号编号。
- 复用现有单一区域 Durable Object 保存屏蔽关系，避免发现列表、邀请接受和屏蔽之间的并发竞争。列表接口只返回随机屏蔽记录编号、匿名代号和日期，不返回真实账号编号或对方的屏蔽关系。
- 所有公开接口先校验账号、同源请求及请求体大小。解除只能影响当前账号的列表；只有房间参与者可通过房间编号屏蔽对方。
- 屏蔽关系与待关闭房间一起持久化，再执行房间关闭。临时失败由持久化 alarm 重试，服务对象重建不丢任务；客户端主动退出本次共听并停止本机音频。已完成交换的补存沿用原流程，未完成交换结束。
- 当前仅有一个示意区域；真正多区域接入前，需要将关系查询提升为跨区域的账号级服务。清空身份并重新创建账号仍可绕过，不将本地身份当作正式反滥用体系。
- 本轮不新增举报处理、封禁、真实地理匹配或公共服务限流体系；原邀请冷却继续生效。

## 验证

- `npm run test:blocking`：旧区域数据迁移、关闭失败后的持久化及对象重启重试。
- `npm run test:blocking:integration`：双向隐藏、拒绝邀请、刷新身份恢复、重复请求、双向屏蔽的独立解除、账号隔离、邀请取消、共听停止、接受与屏蔽竞争、请求校验及内部接口隔离。
- `npm run test:recovery` 新增二次确认、失败重试和切号后迟到响应隔离；保留原播放、通知、雷达与恢复测试。

本轮验证：上述 28 项测试及当前歌单、登录、回歌持久化、已读的 6 项集成回归通过（合计 34 项）。浏览器 A/B 实测屏蔽后双方隐藏、设置读取列表、解除后重新相遇；390px 确认区域无横向溢出。TypeScript、lint 与生产构建检查通过；不代表真机或公网验收。
