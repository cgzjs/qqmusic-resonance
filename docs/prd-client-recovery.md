# v0.9 后台恢复与断网状态

更新：2026-09-21。本阶段继续使用模拟宿主与演示区域，沿用已有邀请、共听、交换和账号记录协议。

## 目标与交互

| 场景 | 预期行为 |
| --- | --- |
| 从后台回到共听页面 | 先暂停本机播放并显示“正在恢复并同步状态”；等待本次状态确认，旧消息不能直接恢复播放 |
| 连接仍有效 | 用一次带时间标记的心跳确认服务器最新状态，再校准播放位置 |
| 连接失效或长时间无新状态 | 重建连接，继续使用原席位凭据；先确认房间仍存在 |
| 浏览器报告离线 | 立即暂停共听、禁用播放和互动发送；恢复网络后重新连接 |
| 换歌操作发送后断网 | 显示结果尚未确认；不自动补发。用户“重试确认”沿用同一操作编号，复用服务端去重 |
| 回到发现页或恢复网络 | 确认最新发现和邀请状态；确认前不能发邀请或接受旧邀请 |
| 邀请倒计时 | 使用服务器时间偏移计算，独立于轮询更新；倒计时归零即禁止回应，等待服务器确认最终结果 |
| 离线时主动暂停发现 | 本机立即停止发现，不因网络恢复而自动开启；服务器离线记录按已有 30 秒期限清理 |
| 发现会话过期 | 清除过期听众和邀请，提示重新开启；不自动公开当前歌曲 |
| 主动退出或房间已结束 | 后台恢复、网络恢复不自动重新进入 |

后台期间不主动禁止正常共听；浏览器如果挂起音频或网络，返回时按上述确认流程恢复。重新建立连接会沿用服务端的掉线暂停规则，不自动替用户发送“播放”。系统要求重新触发音频授权时，保留原有开启声音入口。

## 已实现

- 房间状态确认门槛同时约束音频、播放控制、轻回应和交换发送，避免 React 尚未更新界面时使用旧状态。
- WebSocket 的 8 秒连接期限覆盖收到有效欢迎消息之前的阶段，避免连接打开但验证未完成时一直等待。
- 发现请求按页面生命周期隔离；后台前排队的点击不会在恢复后补发，迟到的发现响应不会重新启用已暂停的状态。
- 已结束房间清理待确认交换状态；轻回应保留原有短时有效期，不做离线补发。
- 现有服务端邀请超时、房间席位保留、交换去重与账号持久化规则不变。

## 验证与边界

`npm run test:recovery` 使用真实 React hooks、音频协调逻辑和发现面板，在 DOM 环境中控制网络事件、时间和传输响应，覆盖后台状态确认、掉线恢复、交换重试编号、验证超时、过期房间、邀请过期、迟到响应以及主动暂停。传输层和音频设备是测试替身；这些测试不代表真机或公网验收。

本轮验证：9 项客户端恢复测试通过，TypeScript、lint、生产构建通过。独立本地 Worker 中的 6 项附近邀请、2 项交换集成测试通过，包含真实 45/60 秒超时；1 项共听集成测试并行首跑发生 `ECONNRESET`，单独重跑通过，未放宽断言。开发预览已恢复，`/nearby` 返回 200。

开启发现的响应若彻底丢失，本机可能未拿到发现凭据；此时明确提示等待，服务器未续期的记录最多保留 30 秒。本阶段不增加自动重开或后台操作队列。
