# v1.2 双页面登录与体验收尾

用途：方便本地打开两个页面，以 A/B 两个账号验证共听。继续复用现有模拟宿主账号服务，不新增注册、密码或 QQ 官方授权。

## 登录规则

- 没有选过身份的新标签页显示登录入口，不再默认进入 A。
- 选择“听众 A / B”后进入附近。标签页只在自己的 sessionStorage 记录选择，刷新后恢复该账号。
- 账号身份和各账号选曲继续保存在原有浏览器本地资料中，收藏、足迹、未读与待回应记录仍由账号服务保存。
- 同时首次登录相同身份时，浏览器支持 Web Locks 的情况下串行创建，避免两个页面生成不同的 A。
- 页面有“切换账号”和“退出登录”。切换先停止当前页面的发现与播放，再选择另一身份；普通退出只撤销本页授权，不撤销其他页面的会话。
- 登录异步结果按请求代数校验，较晚返回的旧登录不能覆盖新选择。
- 本地调试里的“打开另一个双人联调页面”使用独立窗口上下文，不携带账号令牌，也不复制当前页的选择。
- 双人发现仍需各自手动开启；同一账号不能在两个页面占用两个听众席位，应分别选择 A、B。
- 开发模式仍仅在本机启用，生产构建默认关闭模拟授权；正式 QQ 登录待官方接入条件明确后替换。

## 测试步骤

1. 两个页面打开 `/nearby`（默认真人互通），分别登录 A、B；旧 `?mode=online` 地址继续可用。
2. 双方点“开启发现”，一方邀请、另一方接受，再各自开启声音加入。
3. 测试共听、暂停、交换选歌、收藏、退出和足迹回看。
4. 刷新两个页面，确认账号不串；退出 A，确认 B 仍可操作。

普通 `/nearby` 保持统一的附近体验，默认连接真实客户端。自动回应收进折叠调试区，或通过 `?mode=demo` 打开；未重新引入并列的两个首页入口。接收方在足迹页也会收到邀请侧边提示，在房间收到歌曲或交换完成时也有对应提示。

登录页采用黑底青绿的唱片卡视觉，A/B 分别以青绿、灰蓝区分；复用现有星星与音符素材，悬停和键盘聚焦有唱片轻转反馈，尊重系统减少动态效果设置。保留原有登录按钮和账号逻辑，390px 窄屏下两列可用、无横向溢出。

## 验证

- 登录单元测试验证新页面选择、A/B 隔离、刷新恢复、并发创建同一身份与旧请求覆盖保护。
- 本地服务测试验证单会话退出、其他会话与账号保留、对应发现清理，以及原有全账号撤销兼容。
- 浏览器两个页面实际走通 A/B 登录、刷新、发现、邀请、双端播放、交换与收藏；一方结束后两端停止，一方退出登录不影响另一方。
- 修复从收藏或待听进入试听后返回分类丢失的问题，返回保留原分类；浏览器验证收藏重播和返回。
- TypeScript、lint、生产构建与原客户端恢复测试通过。仅为本地双页面验收，不代表真机或官方宿主接入。
