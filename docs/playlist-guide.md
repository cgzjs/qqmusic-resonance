## 添加一首歌

1. 音频放到 `public/audio/`；封面可选，放到 `public/covers/`。
2. 在 `config/playlist.json` 的 `tracks` 数组加入记录，例如：

```json
{
  "id": "my-song-001",
  "title": "我的第一首歌",
  "artist": "歌手名称",
  "audio": "/audio/my-song.mp3",
  "cover": "/covers/my-song.jpg",
  "accent": "#6feee1",
  "source": "自备模拟歌单"
}
```

`id`、`title`、`artist`、`audio` 必填，其余字段可省略。不要填写时长，程序会从音频文件读取。没有封面或浏览器加载封面失败时，继续显示默认专辑图形。

3. 运行 `npm run playlist:prepare`，检查是否有错误，然后刷新浏览器。`npm run dev` 和 `npm run build` 也会自动执行准备；修改文件后重启预览即可。

准备过程会校验重复 ID、文件存在、路径范围和可读时长，生成 `lib/resonance/catalog.generated.json`。解析失败不会覆盖上一份清单；修正配置后重新运行。

## ID、删除和恢复

- ID 使用小写英文字母、数字和连字符，最多 64 字符，不能重复。
- 同一首歌改标题、歌手、封面或重新编码音频时，可以保留 ID；换成另一首歌时使用新 ID，避免旧收藏变成另一首歌。
- 从 `tracks` 删除一项并重新准备，即从当前播放/交换歌单中下架。旧收藏、待听与历史不会被删除，页面标记不可播放，仍可手动取消收藏或移出待听。
- 生成清单保留已下架歌曲的最后名称、歌手等资料。请保留并随配置一起提交这个文件，不要手动清空其中的 `retired`。即使缺少历史资料，账号里的旧 ID 仍显示为已移除条目，不会导致页面崩溃。
- 用相同 ID 重新加入原歌曲并准备后，原收藏可恢复播放。
- 空歌单显示空状态及已有记录；只有一首歌时可试听/共听，但交换需要至少两首。

## 文件范围与播放方式

- 音频扩展支持 WAV、MP3、OGG、M4A、FLAC；本轮实测 WAV 和 MP3，其余格式需在目标浏览器确认编码兼容性。
- 最多 100 首，单首不超过 32 MiB；封面 PNG/JPG/WebP/SVG 不超过 5 MiB。
- 使用本地文件路径，不接受远程音频 URL。中文文件名可用，生成清单会处理 URL 编码。
- 元数据读取采用 [music-metadata](https://github.com/Borewit/music-metadata)，只在准备/构建阶段使用，不进入浏览器播放器。
- 当前仍使用完整缓冲来兼容不支持 HTTP Range 的静态环境，加载超时为 60 秒。这适合少量模拟歌曲，不是流媒体曲库方案。

## 歌单更新与会话

页面底部可直接展开“播放列表”选歌，也可使用上下首、播放/暂停和进度条；不再需要进入调试区换歌。当前播放与附近公开曲目保持一致，收藏/足迹中的试听也会更新底部播放栏。

前后端共用生成的歌单及真实时长。音频/封面带内容版本，替换后不继续命中旧素材缓存；同步服务不再固定为 24 秒。

歌单更新会结束使用旧版本的会话，避免两端使用不同音轨或时长；已经完成的交换结果仍可继续补存。旧页面收到不同版本时会提示刷新。请把音频、配置和生成清单一起更新后再重新邀请。

封面页中的艺人/曲名是固定的视觉示例，不播放那些录音；进入插件后的雷达、播放器、选歌和收藏才使用这里的歌单。
