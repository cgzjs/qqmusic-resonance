# 同频 PRD v0.3：同步播放基础（历史方案）

> 产品入口已由 [v0.4 附近在线邀请](./prd-nearby-invitations.md) 替代。以下保留旧实现与验证记录；复制链接邀请好友不再是产品流程。

日期：2026-09-20；范围：本地开发与构建可运行，不包含公开部署。

## 目标

两个独立客户端通过同源服务连接同一房间，真实同步现有四段内置音频的选曲、播放、暂停和进度。单人演示继续保留；房间中不使用模拟听众或自动模拟回应。

## 本轮交付

1. 房间服务：复用现有 Cloudflare Worker，Durable Object 保存每个房间的权威状态，WebSocket 推送。
2. 邀请流程：选择试听 → 创建房间 → 复制邀请链接 → 对方点击加入。最多房主和一位成员。
3. 播放权限：房主控制公共播放/暂停/选曲/拖动；成员只控制本机声音。浏览器阻止音频时显示开启声音入口。
4. 同步：服务端记录曲目、基准进度、服务端时间、播放状态和递增版本；客户端使用往返时间校准时钟，按差值纠偏。曲目只能来自固定曲库。
5. 生命周期：连接断开暂停播放，有限退避重连；同一客户端重连可恢复原席位，其他客户端不能直接顶替在线成员。主动离开立即释放成员席位；房主主动结束关闭房间。
6. 过期：房间最长 2 小时；掉线席位保留 90 秒，房主超时离线后结束房间。心跳超时关闭失效连接。

## 用户界面

- `/room`：简洁的曲目选择与创建入口；体验页可以带当前曲目进入。
- `/room/[roomId]`：加入按钮、房间连接状态、两位参与者、共享曲目和进度、房主控制、音量、邀请链接及离开按钮。
- 分享的是成员邀请链接，不能分享房主管理凭据；链接凭据放在 URL fragment，通过 WebSocket 首条消息提交。
- 打开邀请不会自动替用户播放；加入后如果浏览器阻止播放，需点击开启声音。
- 内置短音频先完整缓冲为本地 Blob，保证不支持 HTTP Range 的静态环境也能拖动与校准；切歌或离开时释放缓冲资源。
- 断线时暂停本机音频、禁用公共控制；重连读取最新快照，不重放旧命令。

## 协议与限制

- 创建 API：POST `/api/rooms`，只接受本曲库的 trackId。
- 连接：GET `/api/rooms/:id/socket` WebSocket upgrade；首条 hello 携带房间凭据和该标签页的 clientId。
- token 决定房主/成员角色，角色不能由客户端自报升级。令牌不出现在服务端 URL 或普通广播中。
- 命令包含 id 与当前 revision，服务器拒绝过时命令并返回新快照；重复命令不重复执行。
- 来源校验、消息长度、速率与人数限制；不获取账号、真实姓名、定位、麦克风，不接受任意音频 URL。
- 邀请持有者可加入空余成员席位。此能力模型仅用于匿名试听原型，正式公开版本另行设计账号与滥用治理。

## 验收

- 两个客户端同时在线，人数真实为 2；第三个独立成员被拒绝。
- 房主播放/暂停/拖动/换曲都能到达成员；成员发公共控制命令被服务器拒绝。
- 稳定本地网络下两端进度差目标不超过 0.5 秒；如测量环境不支持，明确记录未验收项。
- 重连恢复席位和最新状态；主动离开后人数更新，房主结束后旧链接不可继续使用。
- 无效凭据、非法曲目、错误版本、重复命令及过大消息均不破坏状态。
- 自动化协议/服务集成测试、浏览器双客户端测试、类型检查与生产构建。

## 不在本轮

## 验证记录

- 7 项协议测试通过：时间推算、房主权限、旧版本拒绝、结束重播、曲库白名单、消息格式、时钟偏差，以及结束快照停在结尾的回归用例。
- 真实 Worker / WebSocket 集成测试通过：双人加入、无效凭据、第三人拒绝、成员控制拒绝、播放/暂停/拖动/换曲、重复命令、掉线席位保留、房主及成员重连、主动离开和结束后不可加入。
- 两个独立浏览器标签页实际 audio 元素均播放同一音源；一次稳定播放采样进度差约 0.014 秒，启动采样约 0.139 秒。这是本机开发环境采样，不代表公网或其他设备性能承诺。
- 房主暂停后两端均暂停，键盘拖动到结尾后两端均为 24 秒；换曲后两端音源一致。成员刷新后点击进入可恢复房间曲目。
- 独立 Worker 重启后，两端无需点击重新加入即恢复在线，最终实际音频位置均为 21.6 秒，且保持暂停。超过自动重试次数后可通过手动重连恢复。
- 完整音频缓冲后，生产浏览器的 seekable 范围为 0–24 秒；刷新/晚加入可恢复暂停进度。此前静态环境不返回 Range 响应造成无法跳转的问题已修复。
- 最终 `npm run build`、TypeScript、ESLint 通过；原单人 8 项测试、房间 7 项协议测试、1 项真实服务综合测试通过。375px 房间页面未发生横向溢出。

## 验证环境限制与发布前事项

- 当前验证基于本机开发服务及同一生产构建在独立 Miniflare/workerd 中的运行，未进行公网部署或跨设备网络验收。
- Wrangler 本地代理曾间歇返回「worker restarted mid-request」503；隔离构建副本后仍有复现，不能宣称该代理问题已解决。独立 Worker 运行产物的服务测试与浏览器同步测试通过。
- 当前 Vinext beta 的生产预览曾出现 RSC prefetch setup 报错，已确认实际路由、创建/加入与播放可用；正式发布前应复查/处理框架预取问题。
- 真实 iOS/Safari、长时间后台、两小时自然到期和公网延迟仍需补充环境验收。权限、版本、过期判定、人数限制和资源释放已有代码与测试覆盖。
