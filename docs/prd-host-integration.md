# 同频 v0.5：QQ 音乐宿主状态与账号数据

> 界面与数据整合已由 [v0.6](./prd-integrated-experience.md) 更新：`/experience` 回到统一主入口，原功能直接融入主界面；新增账号待听列表及模拟事件，原匿名本机缓存不自动迁移。

日期：2026-09-20。定位是 QQ 音乐内嵌功能插件，不是独立社交应用。当前只开发本地原型，未取得或接入 QQ 音乐官方插件 SDK、登录验证接口、曲库授权、地理发现接口。

## 用户流程

封面演示入口 → 插件首页 → 读取宿主登录态及当前歌曲 → 用户主动开启附近发现 → 邀请与接受 → 一起听。

- 首页直接展示当前歌曲、附近发现状态和“我的音乐”，不再要求先手选试听再进入。
- 不提供插件自己的注册表单、QQ 密码输入框或额外账号体系；宿主未登录、授权过期、读取失败各有明确页面状态。
- 登录不等于同意公开音乐。发现默认关闭，退出、切号或失效时清空当前界面和发现状态、停止本机播放。
- 对外仅展示临时匿名代号和歌曲，不广播宿主账号 ID、昵称、授权凭据。
- 当前曲目变化会更新公开歌曲，同时撤销尚未完成的旧曲目邀请；没有可用曲目时暂停发现。
- 双人会话仍用内置合成试听和已有同步播放器；未控制 QQ 音乐真实播放器。

## 本轮可运行内容

### 模拟宿主

`lib/resonance/host-protocol.ts` 定义应用自有 `HostAdapter` 契约（restore / requestAuthorization / subscribe），不是官方 QQ API。`demo-host.ts` 实现它；真实适配器及服务端授权码校验尚待官方接入资料。

本地浏览器模拟宿主 A/B 账号及当前歌曲。默认模拟宿主已登录；账号、曲目控件放在“模拟宿主 · 本地调试”折叠区；可模拟退出及授权失效。不会采集真实 QQ 密码、Cookie、登录令牌或个人位置。

- 模拟账号由服务端生成唯一 ID 与随机设备证明，设备证明只用于本机模拟宿主恢复身份，不能代表 QQ 认证。
- 模拟宿主身份及选曲写在 `resonance.mock-host.*` localStorage；标签页选择哪个模拟账号放在 sessionStorage。短期插件会话令牌只存在内存中，刷新通过模拟宿主重新授权恢复。
- 服务端仅保存凭据 SHA-256 摘要，短期令牌有效 2 小时、每账号最多 8 个有效会话。模拟退出撤销账号所有短期会话；再次模拟登录仍恢复同一账号的数据。
- 开发配置显式开启 mock，且服务限制 localhost/127.0.0.1/::1；生成生产配置默认关闭 mock。公网缺失真实宿主时显示等待连接，不自动创建假 QQ 账号。
- 不能将模拟宿主设备证明机制直接用于正式 QQ 接入；真实授权与续期必须由宿主和服务端验证链处理。

### 账号数据

`PluginAccount` Durable Object 按账号隔离持久化收藏和最近 100 条同频收听记录。写操作由服务端鉴权并逐项应用，调用者不能只改 accountId 就读写别人的数据。重复记录 ID 不重复入库；只允许现有试听曲库。

- 收藏在插件内点击保存/取消，刷新或退出再登录后保留。
- 同频音频真正进入 playing 后记一条收听事件，不把收到邀请或加入会话算成已听。
- 切号立即清空前一账号的内存数据和会话入口缓存，忽略旧账号迟到的请求响应；新账号单独读取服务端数据。
- 失败明确提示，没有离线写队列，不显示虚假的已同步状态。
- 原 `/experience` 是旧的独立单人演示，仍使用它自己的本机模拟记录；不自动迁移到任意账号，也不冒充 QQ 音乐收藏同步。

### 附近与播放权限

附近 API 需要有效插件账号会话和当前发现凭据，两者必须属于同一账号。同一账号最多一处发现，不会看到或邀请自己。新邀请建立的播放会话同时绑定双方账号，加入及后续心跳/命令检查账号授权；撤销授权后关闭会话。

客户端切号、退出、授权失效会卸载发现/播放视图并发送退出；同账号其他页面通过 API 验证发现撤销（发现约 2.5 秒、播放心跳约 4 秒、闲置首页约 10 秒）。网络断开时依赖原有心跳超时。只有明确开启发现时才发布曲目信息。

## 验收

1. 从封面进入直接看到账号、当前歌曲和附近入口，没有选歌向导。
2. 收藏后刷新仍保留；切 B 不显示 A 的收藏，切回 A 可恢复。
3. 切曲同步卡片；无歌曲禁用开启发现。
4. 退出/失效使发现、邀请、播放停止；重新登录恢复同账号数据但不自动开启发现。
5. 双端邀请同步回归，播放产生账号记录；伪造账号标识、无效凭据被拒绝。
6. TypeScript、lint、构建、服务集成测试和浏览器实测。

## 真实接入仍缺少

QQ 音乐宿主 SDK/生命周期文档、可验证的授权交换接口、应用标识与权限、当前曲目及播放接口、真实曲库许可、附近区域实现。取得这些资料后替换适配器及服务端 verifier。本轮不宣称已接入 QQ 登录、QQ 收藏或真实音乐播放。

## 验证记录

- 共 24 项自动化测试通过：8 项原单人逻辑、7 项同步协议、1 项原同步服务、6 项带账号的附近邀请集成、2 项账号持久化/隔离集成。账号和附近集成还在独立 Miniflare/workerd 生产构建中开启本地测试 mock 后通过。
- 浏览器已验证 A 收藏后刷新恢复，切 B 无 A 收藏，切回 A 恢复；模拟退出后刷新维持未登录；无当前曲目时不能开启发现。
- A/B 两页在带账号授权的会话中播放同一试听，双方真实 audio 为 playing，各自账号出现收听记录。模拟授权失效移除本机 audio，对方暂停；离开与 socket close 竞态补了服务回归。
- 375px 生产页面已截图检查，无横向溢出。默认生产配置 `DEMO_HOST_ENABLED=false`，浏览器呈现等待宿主状态；只有本地验证 helper 显式开启模拟宿主。
- TypeScript、ESLint 与生产构建已通过。开发途中增加 Durable Object 绑定触发热重启失败，完整重启本地开发服务后恢复；未掩盖框架错误。
- 未接入真实 QQ 登录/账号/歌曲或地理服务，未公网部署。v0.3 中的 Vinext beta 与 Wrangler 预览限制仍适用，未宣称本轮修复。
