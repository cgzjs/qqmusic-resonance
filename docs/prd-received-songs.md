# v1.0 收到的歌与未读提示

本轮只完善回歌收件体验；刷新恢复未完成回应、统计口径统一留待后续。真机测试暂缓。

- 足迹中增加“收到的歌”，汇总已完成的场景交换与在线双人交换，不新增独立页面。
- 按交换记录去重，不按歌曲去重；同一首歌被不同听众送来两次，保留两次相遇。
- 新回歌在底部“足迹与收藏”和“收到的歌”分类显示未读数量。有未读时，点击底部入口直接打开回歌列表。
- 打开列表不自动清空未读；展开某首回歌后保存已读状态，并显示送出/收到的歌曲和试听入口。
- 已读状态保存到当前账号，刷新或重新登录后保持；不同账号隔离，不能修改其他账号的交换。
- 保存失败继续保留未读，显示重试；歌曲下架仍可查看记录和标为已读，禁用试听。
- 升级前的历史交换初始化为已读，避免突然出现大量旧消息提醒；历史记录仍可查看。
- 未读来自已成功保存的交换，关闭侧边弹窗不等于已读。点击弹窗/回歌入口查看结果时也确认已读。

验收：等待期间切走 → 收到新歌 → 导航角标 → 收件列表 → 展开清除单条未读 → 刷新仍已读；验证账号隔离、重复交换投递、保存失败与下架歌曲。

## 本轮验证

- 回应/恢复组件测试与回歌规则测试共 16 项通过，包含离开面板后收件、失败重试、下架歌曲可读、按交换去重与来源隔离。
- 2 项真实本地服务集成测试通过：账号重新登录后保持已读、重复标记幂等、越权与未知回歌拒绝、双人交换重复投递不恢复未读。
- 浏览器验证新回歌角标、进入收件列表不清除未读、展开单条清除及试听入口；原历史记录仍存在且不标新消息。
- TypeScript、lint 和生产构建通过；本轮不包含真机或正式 QQ 接入验收。
