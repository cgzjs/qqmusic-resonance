## 定位与原则

同频是 QQ 音乐内嵌功能插件，复用宿主账号与当前歌曲，不独立注册。目标是让附近的陌生人因为音乐产生低压力的短暂相遇，车站、校园、咖啡店只是场景，不限定同车厢。

1. 音乐先于身份，对外显示匿名代号和音乐。
2. 登录不等于开启发现，公开音乐由用户主动选择。
3. 邀请被接受后才建立双人共听；用户随时可退出。
4. 附近只表达粗粒度区域，不展示精确位置。
5. 保留原有雷达、详情、跟听、交换和足迹，新增服务接入这些流程，不另做缩水首页。
6. 模拟与真实客户端交互明确区分，不把演示区域或宿主模拟当成真实 QQ 接入。

## 入口与功能

新增“地点留声”：自动读取当前位置，展示 500 米内的音乐留言，并把歌曲与留言留在当前位置附近；留言支持文字、手绘或 AI 图，没有手动选点或坐标输入。后来经过附近的人可反复听歌、查看图片、朗读文字和收藏，不要求双方同时在线。单人体验使用隔离的预置位置；正常模式需允许浏览器定位，详见 [地点留声说明](./prd-location-music.md)。

单人体验入口只放在登录页：A/B 卡片用于正常双页面联调，另有“单人体验”按钮直接使用 A 身份进入。模拟听众与自动回应说明集中在登录入口；内部沿用正常雷达、共听、送歌与足迹，不新增模式标签、偏好文案或教学提示。体验中每首歌对应一位听众，可通过封面或歌曲标签选择；喜欢后自动回应，送歌记录按现有流程查看。选择保存在当前标签页，刷新后继续原模式；重新选择 A/B 登录切回正常双人模式。设置中的听众来源选项仍保留调试兼容。

| 入口/状态 | 内容 | 当前程度 |
| --- | --- | --- |
| `/` | 封面及进入同频 | 已完成 |
| 登录入口 | 选择 A/B、刷新恢复、切换与退出 | 本地联调账号，复用现有服务；不新增注册或正式 QQ 授权 |
| `/nearby` → 附近 | 主动发现、真实客户端邀请、接受/拒绝/撤回/超时 | 默认连接真实客户端，双方开启发现并接受邀请后共听；区域仍不代表实际地理距离 |
| 登录页 → 单人体验 | 多首歌曲及体验听众、共听、自动喜欢回应、送歌 | 入口说明数据来源；内部按正常流程使用，送出的歌记入当前账号足迹，不向另一个登录账号发歌 |
| `/room/:id` | 双端播放、表情、互相选歌交换、退出/重连 | 已完成，使用自备模拟歌单；交换有独立回应与账号记录 |
| 足迹与收藏 | 足迹、收到的歌、收藏与待听、播放及移除 | 回歌有未读提示，展开后按账号保存已读；同一首歌的不同交换分别保留 |
| `/experience`、`/room` | 旧地址兼容 | 重定向到统一首页 |

首页统一为“附近”，默认真人互通；体验方式仅在登录页选择，内部不显示单人/双人模式切换。`?mode=demo` 与 `?mode=online` 保留调试兼容，已保存的标签页选择优先。内部切换保留播放器；通过调试入口切换到单人模式时退出真实附近分享并清除邀请提示。进入真实会话停止旧试听。切号、退出或授权失效清理界面及播放。空列表、刷新和暂停状态隐藏雷达中心图标，避免遮挡提示文字。

底部“当前播放”支持播放/暂停、上下首、进度拖动、收藏与展开歌单选曲，和试听、足迹共用一个播放器。播放中上下首继续播放，暂停时切歌保持暂停；点击歌单条目直接播放。切换页面不中断，进入双人房间停止本机旧试听。当前曲目同步到宿主适配状态与已开启的附近发现；切换歌曲沿用原规则撤销旧曲目的待处理邀请。

附近雷达默认可见，采用唱片轨道布局：中心是当前曲目，听众使用真实封面节点，点选后定位邀请入口；空状态保留轨道并显示等待文案，不添加虚构听众。

音乐关联只根据双方当前歌曲显示：歌曲 ID 相同为“与你同曲”；不同歌曲的歌手字段相同为“同一位歌手”。没有匹配依据或没有当前歌曲时不显示标签，切歌与选择听众后重新判断；不推断听众偏好，也不展示未计算的匹配百分比。首页雷达使用音乐相遇示意，登录入口说明附近为演示区域、未读取真实定位。

插件以手机端使用为优先。雷达中央唱片可以直接播放 / 暂停，复用底部播放器；只在当前曲目实际播放时转动并显示扩散光环，支持关闭动效及系统减少动态效果设置。背景采用本地音乐与星光线条素材，随日夜外观着色，不占用点击区域，也不冒充附近听众。

全局支持日间 / 夜间外观，顶栏切换，默认夜间。外观覆盖封面、登录、附近、足迹、播放器、通知及共听房间；本机记住选择，同源窗口同步，不随 A/B 切号重置。背景以当前歌曲封面的柔焦色彩和低对比曲线增加层次；切换外观不改变播放、发现、邀请或账号状态。

真实邀请和交换有独立侧边通知：在附近或足迹收到邀请可点击“查看邀请”；进入同一房间后收到歌曲可点击“选歌回应”定位交换面板，完成后双方收到对应回歌提示。心跳更新不重复弹出，邀请结束/退出房间清除过期提示。登录 A/B 本身不会自动开启发现或替对方接受邀请。

主机收到一起听邀请后，可以从卡片或侧边通知选择“暂不加入”。仅拒绝尚未接受的当前邀请：房间关闭确认后清除邀请，邀请人的等待结束，主机继续当前播放和附近分享；关闭失败保留邀请供重试。重复、过期、其他听众发起的拒绝不能关闭房间，已接受的邀请也不再允许拒绝。

共听专辑两侧的匿名头像对应“你 / TA”：打招呼时发送者头像轻摇，收到实际招呼后才触发对方头像动作；喜欢歌曲为短暂轻弹。送达回执不冒充回应，旧曲目和历史动作不重复播放。提示约 2.6 秒消失，可与回应区一起关闭动效。

共听组件卸载只断开连接，不发送主动退出；刷新或重新挂载沿用当前标签页的房间凭据与客户端 ID，在现有 90 秒宽限内恢复。断线后服务端暂停播放，重新连接后同步暂停位置，由房主继续播放；主动“结束一起听”与邀请人“取消等待”仍结束双方会话。不同账号可以分别占用房主和听众席位，同一席位仍禁止其他客户端抢占。

当前界面预览按用户要求使用正式体验文案：日常页面、足迹与回复提示不再显示“模拟 / 演示 / DEMO”，技术标识保留在折叠调试区及本文档中。暂停发现显示“发现已暂停”，仅保留“继续发现”操作。此调整仅涉及呈现，不改变自动回应、账号或区域的数据来源；上线前仍需检查真实接入及对外说明。

场景演示的挥手、喜欢和歌曲交换会等待约 2.6 秒再模拟对方回应。等待时可离开面板，继续逛雷达、在线听众或足迹；回应到达后出现右下角提示，点击可查看对应歌曲或回歌结果，不自动打断当前页面。提示约 8 秒后收起，切换浏览器标签期间暂停收起计时；回歌另保留“查看”入口。已确认发送的等待按账号保存，刷新或重新登录后按原截止时间恢复；切号不混入其他账号的回应。交换结果与足迹保存后才提示完成，同一请求不重复记账，通知只认领一次；真实双人互动不自动生成回应。

## 数据与接入边界

参赛体验已增加独立的 `preview` 账号范围、精确访问 origin 开关与本地生产预览命令，详见 [部署准备](./contest-deployment.md)。它复用现有流程，但账号数据、附近状态和浏览器身份与本机联调隔离；默认关闭，尚未发布，不能视为正式 QQ 接入或公网验收。

- “今日交换”合并场景回歌和在线双人交换，按本机当天的完成时间统计；与收件箱采用相同交换编号去重。重试不重复计数，同一歌曲的不同交换分别计数；未完成的等待不计入，已读或歌曲下架不影响次数。足迹列表也按相同来源及编号去重，统计基于账号当前保留的记录。
- 曲库配置在 `config/playlist.json`，准备脚本读取真实音频信息并生成共享清单；场景样本仍在 `lib/resonance/demo-data.ts`。当前已接入用户提供的四首完整歌曲，旧合成试听资料保留在历史清单中。
- 收藏、待听、最多 300 条场景事件及最多 100 条在线收听记录按模拟宿主账号持久化。刷新/重新授权后可恢复，不同账号隔离。
- 旧浏览器匿名本地缓存不自动归入任意宿主账号；数据仍保留，不冒充 QQ 收藏同步。
- 当前只有本地模拟宿主 A/B 和应用自有适配契约，没有接入官方 QQ SDK、真实授权、真实地理位置或正式曲库。
- 生产默认关闭模拟宿主，当前未公网部署。
