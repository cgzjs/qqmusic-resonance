# 同频 PRD：单人完整体验版

版本：v0.2 · 2026-09-20

> 历史版本记录。原交互已合入 [v0.6.1 统一插件体验](./prd-integrated-experience.md)，主流程记录改为按账号服务端保存；以下本机存储和独立单人入口描述保留为当时的设计依据。

## 1. 目标与边界

让用户完整完成「发现一首歌 → 真正试听 → 匿名交换演示 → 收藏或稍后再听 → 回看足迹」。当前交付是单机交互原型，音频播放和本机记录真实可用，附近听众、匹配分数和对方回应使用演示数据。

本轮不接入真实定位、蓝牙、QQ 音乐账号、商业曲库、远端用户或多人同步。不新增聊天、关注、推荐算法与后台管理。

试听使用随项目提供的四段原创合成音频；体验页的曲名与实际音源一致。封面中的曲名保留为概念视觉示例，封面不播放音频。

## 2. 用户与核心场景

- 首次体验：打开封面，进入体验，选择一个模拟场景和匿名听众，试听音乐。
- 连续体验：返回雷达或进入交换时音频继续播放；通过迷你播放器暂停或回到播放页。
- 交换：选择推荐歌曲，经过短暂的模拟发送过程，收到对方推荐；收藏与稍后再听分别保存。
- 回顾：足迹由本次实际操作生成，收藏、待听与历史刷新后仍可见。

## 3. 功能要求

### 3.1 音乐播放（P0）

- 统一 Track 信息：稳定 ID、曲名、作者、音频地址、封面色、来源说明。
- 使用一个共享播放器，跨体验子页面不销毁，不允许多个音源叠加。
- 播放、暂停、拖动进度、音量、结束后重播可操作；时间读取音频实际时长。
- 首次播放由点击触发。加载中、缓冲、浏览器拒绝播放和资源失败都有可理解的提示及重试入口。
- 换听众仅改变当前浏览对象；点击试听才切换实际音轨。
- 离开播放页保留进度；离开整个体验或主动结束播放停止音频；刷新后不自动发声。
- 跟听页面明确标注为演示，不宣称真实两人在线或真实时间同步。

### 3.2 交换与收藏（P0）

- 交换可从匹配详情或播放页进入，返回时回到实际来源。
- 状态：选择歌曲 → 模拟发送中 → 收到回应 → 收藏/稍后再听。
- 发送中防止重复提交；离开交换页取消尚未完成的模拟响应。
- 同一次交换只记录一次；切换页面、重复点击不产生重复收藏或交换记录。
- 收到的歌不与送出的歌相同；不依赖 suggestions[2] 这样的固定数组下标。
- 收藏与待听分开保存；同一首歌可取消收藏或移出待听。收藏时从待听中移除。
- 支持在回顾页面试听已收藏、待听和收到的歌曲。

### 3.3 足迹与本地存储（P0）

- 保存有时间戳的发现、试听、交换事件，记录当时模拟场景。
- 当天遇见数按听众去重，交换数按完成记录计数；不显示写死的时长、地点或总量。
- 空历史展示引导入口，不展示虚构的活动。
- 收藏、待听、事件使用带版本号的本机存储；不保存精确位置或真实身份。
- 读取时校验结构、版本与曲目 ID；损坏或过期记录安全丢弃。
- 本机存储不可用时仍可操作，提示当前记录只在本次打开期间保留。
- 历史最多保留 300 条，避免无限增长；刷新后不恢复正在发送的交换或自动播放。

### 3.4 场景发现（P1）

- 地铁、校园、咖啡店使用不同的演示听众集合；展示人数根据当前集合计算。
- 切场景后选择有效听众，不能遗留上一个场景的详情。
- 暂停发现隐藏附近列表；重新开启恢复发现。暂停发现和暂停音乐是独立操作。
- 提供手动刷新及搜索中、无结果状态；模拟场景与模拟回应在页面中保持明确。
- 匹配度仍为示例值，不宣传为算法或真实定位结果。

### 3.5 交互与视觉（P1）

- 延续已确认的黑青配色、紧凑排版和简短文案；封面结构保持。
- 按钮具备键盘焦点与可访问名称，进度与音量可用键盘调整。
- 页面转换时内容回到顶部，音频状态独立保留。
- 320px 窄屏无横向溢出；播放器和导航不覆盖内容；减少动态效果时保留功能。

## 4. 状态与数据约定

- 父级统一管理 view、selectedListener、scene、exchangeReturn、交换草稿和播放来源。
- 音频时间以 HTMLAudioElement 为准，不通过计时器伪造进度。
- 展示组件接收数据与回调；可测试的状态更新和存储校验放在 lib/resonance。
- library：favoriteIds、listenLaterIds、events；本地 key 为 resonance.library.v1。
- event：id、type、trackId、listenerId、scene、createdAt；交换另含 receivedTrackId。
- 随机 ID、时间戳只在用户操作/客户端事件中生成，避免服务端渲染不一致。

## 5. 分阶段交付与验收

| 阶段 | 交付 | 验收 | 状态 |
| --- | --- | --- | --- |
| 1 | 可播放音源、共享播放器、正确返回 | 真正播放/暂停/拖动/调音量；切页保留；错误重试 | 已实现，浏览器验收通过 |
| 2 | 交换、收藏、待听与本机保存 | 不重复发送；返回来源正确；刷新后分类记录仍在 | 已实现，浏览器验收通过 |
| 3 | 真实操作足迹与回顾试听 | 空状态正确；统计与操作一致；历史歌曲可试听 | 已实现，浏览器验收通过 |
| 4 | 场景、刷新、异常状态与视觉收尾 | 场景数据不同；搜索/空结果/暂停可恢复；窄屏可用 | 已实现，浏览器验收通过 |

每阶段完成后记录验证结果，再进入下一阶段。不会将演示回应记为真实联网验收。

## 6. 关键验收用例

1. 进入地铁 → 选歌 → 播放 → 暂停：时间停止，恢复继续；拖动跳转正确。
2. 播放 → 返回详情/雷达：进度不重置，迷你播放器可控制；点击另一首后只有新音源播放。
3. 详情直接交换 → 返回：回详情；跟听进入交换 → 返回：回跟听。
4. 发送中重复点击只执行一次；发送期间返回不出现迟到结果。
5. 收藏收到的歌，刷新后仍在收藏；稍后再听进入待听而非收藏。
6. 当天发现、试听、交换后，足迹立即变化；无操作时为空，不出现虚构统计。
7. 切换三个场景，人数与歌曲集合一致；暂停发现、空结果、刷新都能恢复。
8. 音频失败可重试；存储损坏/禁止存储不崩溃；没有真实账号或定位请求。

## 8. 本轮验证记录

- 浏览器读取实际 audio 元素：24 秒时长、播放时 paused=false、暂停后 paused=true；始终只有一个 audio 元素。
- 键盘操作进度与音量；跨页播放、迷你播放器暂停、结束与重播入口均已验证。
- 从匹配详情与跟听两条路径进入交换，返回来源正确；发送中返回后今日交换仍为 0。
- 完成两次演示交换后统计为 2；收藏为 1、待听为 1，分类互相独立。刷新后收藏仍存在且音频未自动播放。
- 从待听列表可以试听对应曲目；足迹起始为空，随后由发现、试听、交换操作生成。
- 地铁 4 人、校园 2 人、咖啡店 2 人的集合不同；刷新经过搜索与空结果，可再次刷新恢复；暂停发现可恢复。
- 临时移走一段音频验证资源失败，显示错误与重试；恢复文件后点击重试可正常播放，测试文件已还原。
- 自动化用例覆盖数据去重、存储往返、损坏/未知版本/未知曲目过滤、历史上限、交换候选、时间格式和音频文件有效性。
- 手机布局已检查；系统禁止存储、真实 iOS/Safari、真实双人同步仍未进行环境验收。存储不可用有降级提示，真实同步不属于本版。
- 最终验证：`npm run test:resonance` 8/8 通过，`npm run lint`、`npx tsc --noEmit --incremental false`、`npm run build` 均通过。
- 320 / 375 / 768 / 1440px 雷达页面无横向溢出；刷新后 audio 为暂停且无自动加载曲目。录音文件故障测试已恢复原文件。
