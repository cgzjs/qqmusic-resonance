# 同频 PRD v0.6.1：统一插件体验与后续计划

更新日期：2026-09-20。v0.6 已完成主流程合并，v0.6.1 补充雷达遮挡修复；v0.7 的双端轻回应与真实交换已实现，详见各专项 PRD，当前验证限于本地模拟宿主和内置试听。

保留原有雷达、场景切换、匹配详情、试听/跟听、表情、交换一首、收藏、待听和足迹，合并进 `/nearby` 插件主入口。`/experience` 重定向同一入口，不再维护两个功能不同的首页。

主导航为音乐雷达、音乐足迹；雷达内切换“场景体验”和“在线听众”。场景体验沿用原模拟数据，明确标记匹配与交换是演示；在线听众使用真实客户端发现、邀请及双端播放，不伪造相似度或距离。账号及宿主当前歌曲保留，登录不自动开启在线发现。

内部页面切换保留在线发现与邀请，并提供全局邀请提示；进入双人会话时停止本地试听，切号或退出也清理播放器和交互状态。收藏、待听、模拟事件及真实同频记录统一保存在当前账号，足迹中区分“场景演示”和“在线同频”。原服务端收藏和历史数据补齐新增字段后继续使用，旧匿名浏览器缓存不自动归属到任何账号。

收藏/待听去重，收藏移出待听；事件幂等，服务端校验曲目、听众和场景；保存失败有提示，交换结果仍可重试。没有新增官方 QQ SDK、真实位置、双人真实交换或聊天。

验收：主入口走通雷达 → 详情 → 试听 → 模拟交换 → 收藏/待听 → 足迹播放与移除；刷新后保留，切号隔离；在线邀请双端回归；小屏、返回导航、音频释放和失败状态检查。

## v0.6.1 雷达状态修复

问题：空状态文字覆盖在雷达上，但原中心图标的层级更高，导致 “YOU” 和耳机挡住“这里还很安静”等文案。

- 在线没有听众、发现尚未开启、模拟雷达刷新/空列表，以及暂停场景时，隐藏中心图标及其光环。
- 普通有听众状态继续显示中心图标；不删除正常雷达节点。
- 空状态文字独立设置覆盖层级、内边距和居中排版，避免窄屏重叠。
- 已检查 375px 空状态、场景刷新后的空列表以及正常节点显示；此修复通过类型检查、lint 和构建，没有新增低收益的样式单测。

## v0.7 真实双人互动（本地闭环已完成）

当前实现及素材见 [双端轻回应 PRD](./prd-reactions.md) 与 [真实双人交换 PRD](./prd-live-exchanges.md)。表情、交换及账号结果已连通；真实宿主、跨设备与公网验收仍不包含在本轮内。

目标：用户在同频会话里真正收到对方的轻互动与推荐歌曲，接通“相遇 → 一起听 → 交换 → 留下音乐”。复用当前会话和账号存储，继续使用内置试听，不等待真实 QQ SDK 才验证本地双端交互。

### 第一步：双端表情（已完成）

- 将原有“打个招呼 / 这首不错”接入在线共听页，两种角色均可发送。
- 服务端确认后，对方显示短暂反馈；本机区分发送中、已发送与失败，不能用本地动画冒充对方已收到。
- 校验当前会话成员身份及账号授权；限制频率、按事件 ID 去重；非成员及已结束会话不能发送。
- 断线不积压表情，重连不重放已过时的动画；不影响播放控制权和进度。
- 验收：A 点击后 B 收到一次，连续点击受控，越权/失效/断网有明确结果。

### 第二步：真实交换一首（已完成）

- 仅在双方已加入的在线会话中开放，两人都可发起；场景演示继续保留并明确标注。
- 发起方选择一首内置歌曲并送出；接收方可选一首回应、拒绝或忽略；不自动生成回应。
- 同时最多一份待回应交换。计划默认有效期 60 秒，使用服务端时间；具体时长可在体验验证后调整。
- 状态：选歌 → 发送中 → 等待对方 → 双方完成；拒绝、撤回、超时及会话结束为独立终态，发送失败保留选择供重试。
- 同时发起时由服务端确定先后，另一端看到现有交换；重复发送、重复回应不能产生第二次完成记录。
- 回应歌曲与收到的歌不同，延续原交换体验。完成后双方分别看到自己送出和收到的歌曲，可收藏、加入待听或关闭。
- 交换不会自动切换公共播放，也不会自动收藏；试听与切换公共曲目沿用明确的播放权限，避免两路声音叠加。
- 完成结果可靠保存，并按稳定交换 ID 幂等写入双方账号；一端保存失败不能显示为双方已保存，恢复后可补写且不重复。会话结束不能让已完成的交换结果丢失。
- 账号足迹标记“在线交换”，与“场景演示交换”区分；收藏和待听继续去重。

### 第三步：连通验收（本地已完成）

- A/B 两端走通邀请、共听、表情、交换、保存、回看和重播。
- 覆盖双向发起竞争、拒绝/撤回/超时、重复消息、断线重连、退出/切号、授权失效及保存失败后的恢复。
- 主导航、原模拟流程与现有收藏/足迹回归；375px、键盘操作和动效减弱状态检查。
- 不把聊天、好友关系、正式曲库、真实定位或公网部署混入此轮。
