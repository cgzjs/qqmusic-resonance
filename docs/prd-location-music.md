# 地点留声：同一个地方，听见不同人的歌

在地铁站、公园、校园或街角留下歌曲和一段话，后来的人打开同一地点，可以阅读、听留言、试听歌曲并收藏。留言留在地点，允许多人反复听；没有随机捞取、领走、自动回复或聊天关系。

打开留声入口即通过浏览器请求当前位置，自动展示附近 500 米的音乐留言；没有地点选择器、地图选点或坐标表单。发布、刷新和重试都重新读取位置。定位权限被拒绝、定位超时或误差超过 500 米时提示重试，正常模式不回退到预置位置。浏览器定位需要用户允许权限以及 HTTPS 或可信本机环境，见 [Geolocation 文档](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition)。

登录页“单人体验”使用预置位置与独立地点留言，不请求用户真实定位；说明集中在登录入口。正常 A/B 模式使用各自设备上报的当前位置，不预置虚构的用户留言。账号范围沿用已隔离的本机联调 / 参赛预览；服务仍未公开发布。

服务端校验定位坐标、精度及时间戳，过期超过两分钟的定位不能用于操作；只返回 500 米内的留言。发布时自动复用 150 米内的最近地点锚点，否则建立一个约百米精度的留声锚点。精确定位只用于当次请求，不写入留言存储、不放进 URL 或待重试存储，也不记录位置轨迹。所有写入验证已登录账号；仅作者可收回留言。对外不返回账号 ID 或令牌，作者标签匿名。定位基于客户端上报，不等同于不可伪造的到场证明。

每条内容为歌单内一首歌、40 字以内标题和 600 字以内留言。歌曲使用现有播放器；留言由浏览器语音合成朗读，不是真人录音。朗读前暂停音乐，点击听歌或重新定位停止朗读；不支持朗读时保留文字阅读。收藏进入现有账号收藏。

留歌入口收成“声音明信片”：默认展示唱片封面与短文案，点击后打开填写面板。收起保留当前页面草稿，确认发布成功后才收起并清空留言；失败留在面板内重试。附近列表提供独立“刷新歌曲”入口，重新读取当前位置并拉取最新留声，不随机生成新歌或伪造他人留言。

声音明信片支持三种内容：文字、手绘和 AI 图。手绘在浏览器画布完成；AI 图通过 `/api/ai/place-image` 优先调用可选的 Cloudflare AI 图片模型，没有绑定时使用项目内的原创 AI 氛围图作为演示兜底。三种内容都要由用户确认后发布，图片只保存受限的图片数据或项目内资源路径。文字模式另提供“AI 灵感文案”：用户可选择温柔、文艺或简短语气，生成三条基于当前歌曲和艺人的候选标题与留言，点击候选后仍可继续编辑。请求不携带精确位置。

服务端串行写入，重复请求 ID 幂等，不因断线重试重复发布；未确认请求在当前标签页保存，重新打开后可重试。每账号 30 秒最多发布一次。原型最多 100 个地点、每地点 100 条活跃留言、共 1000 条记录；容量不足明确提示，不静默覆盖。已确认内容按服务端存储保留，作者收回后从墙中隐藏。

尚未完成不可伪造的到场验证、上传真人语音、内容审核管理、跨设备收藏通知及公网/真机验收。后续若开放公众自由留言，应先补齐内容治理；当前工作不修改线上权限或部署。

验证：`npm run test:places`；运行本地开发服务后执行 `npm run test:places:integration`。自动定位错误分支使用测试坐标验证，单人界面、日夜外观及共享播放器通过浏览器另行验证；未用测试坐标代替真实手机定位验收。
